VERIFYING THE MARIMO CONVERSION
qualtrics_processing_pipeline.ipynb  ->  qualtrics_processing_pipeline.py

Files in this bundle
--------------------
qualtrics_processing_pipeline.py   the converted marimo notebook
make_test_fixture.py               builds a synthetic Qualtrics export
qualtrics_test_export.xlsx         a pre-built fixture (78 rows x 31 columns)
verify_conversion.txt              this file


Environment variables
---------------------
The original notebook opens two tkinter dialogs: one to pick the input .xlsx and
one to pick the output folder. Those still work. Two environment variables now
bypass them so the notebook can run headlessly.

  QUALTRICS_INPUT    path to the raw Qualtrics .xlsx
  QUALTRICS_OUTPUT   folder to write the generated files into

Unset either one and you get the original dialog for that step.


One-time setup
--------------
  pip install marimo pandas numpy openpyxl

TEST 4  dependency graph
------------------------
Marimo re-derives the dataflow graph from the code rather than trusting the
`def _(deps)` signatures. If a signature or return tuple were wrong, or a name
were defined in two cells, or the graph had a cycle, this command fails.

  marimo export script qualtrics_processing_pipeline.py -o flat.py

Expect exit code 0 and a flat.py around 3200 lines.

Regenerating the fixture
------------------------
  python make_test_fixture.py my_fixture.xlsx --rows 200

The seed is fixed at 20260805, so a given --rows value always produces the same
file. The fixture deliberately contains: 4 survey previews, 2 spam responses,
5 straight-liners, 6 partial completions, a Q5 column mixing integers with free
text ("about 10 hours", "8-12", "n/a") to exercise the contaminated-numeric
handler, a Q2# matrix block to exercise the series detection, a date column
stored as text, and blank open-text answers.


Known non-issues
----------------
1. On pandas 3.x you will see a Pandas4Warning about select_dtypes and 'str'
   dtypes, raised inside create_variable_summaries. It comes from the original
   notebook code, which was preserved verbatim, and does not affect output.

2. analysis_ready_data.csv contains flag_duration_too_short and
   flag_duration_too_short.1. The duplicate suffix comes from the pipeline
   adding the same quality-flag columns twice; the .1 is pandas deduplicating
   on write. This is original notebook behavior, not a conversion artifact.

3. Row 0 of the fixture triggers "[WARNING] Row 0 may not contain typical
   Qualtrics question text" followed by "codebook_source: mixed". The real
   pipeline hits the same branch on many exports. Both paths produce a valid
   codebook.
